Overview

The RAPID Hand is an open-source dexterous robotic hand driven by 20 DYNAMIXEL servos. I assembled it in Purdue's MARS Lab and took it from a kit of parts to a hand where every actuator answers on the bus, can be diagnosed and returns to a known pose. Now I'm working on teleoperating it with an Apple Vision Pro.

The challenge

A 20-servo hand fails in many small ways: a wrong ID, a loose shaft, a voltage drop on a shared bus, two joints that move each other. Before any teleoperation or learning work can happen, every actuator has to be reachable, observable and calibrated, and mechanical problems have to be told apart from control problems.

What I did

Assembled the hand

Built the hand and wired 20 XL330 and XC330 servos onto one shared TTL bus.

Brought up the bus

Verified responses from IDs 0–19 at 4 Mbps through a U2D2 interface, confirming every actuator was addressable before running motion.

Built diagnostics

Wrote Python tools with the DYNAMIXEL SDK that log position, voltage, operating mode and hardware errors for each actuator to CSV, so faults are isolated from data instead of guessed.

Bench-tested motion

Sent position commands from Python and documented mechanical coupling between two knuckle axes: moving one joint shifts the other.

Designed a calibration fixture

Designed a 3D-printed fixture that holds the hand in a known pose to record reference positions for all 20 actuators.

Fixed the mechanics

Troubleshooting traced looseness to the bevel-gear supports, so I redesigned them for the 5 mm shafts.

Teleoperation

Now mapping hand tracking from an Apple Vision Pro to the hand's joint commands.

Results

  • All 20 actuators addressable and responding on a single 4 Mbps bus
  • Per-actuator CSV logs that make a failing servo, a voltage problem or a mode error visible at a glance
  • A repeatable reference pose for calibration, set by the fixture rather than by eye
  • Knuckle coupling documented, so it can be compensated in control instead of mistaken for a fault
  • Bevel-gear play removed with the redesigned supports

What I learned

Make the system observable first. Once every actuator reported its own state, most "control" problems turned out to be mechanical: a loose support or a coupled joint. Logging to CSV turned debugging from guesswork into reading a table.
